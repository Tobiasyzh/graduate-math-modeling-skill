# 评审、交付与答辩

本清单用于内部检查，不是官方评分表，不输出“预计国一概率”。审查与问题相称：局部修改检查相关链路，完整交稿才做全稿审计。

## 先查会改变答案的问题

| 维度 | 通过需要看到的证据 |
|---|---|
| 切题 | 每小问及指定结果表/格式均有对应输出 |
| 数学 | 定义一致、单位自洽、假设不删除关键约束、变换有效 |
| 计算 | 命令实际运行、目标与硬约束独立复算、停止条件正确解释 |
| 统计 | 划分符合独立单位与预测时点，预处理在训练折内 |
| 可靠性 | 同口径基线、关键消融/敏感性、失败场景和边界 |
| 证据 | 主张可定位到结果/推导，正文/表/图/摘要数值一致 |
| 表达 | 各段回答问题，重要图表能独立理解，符号/单位/图号连贯 |
| 诚信与规则 | 引用真实、AI披露真实、模板/匿名/截止节点符合本届 |

发现问题按“定位—实际影响—证据—最小修复—复验”输出，不泛泛说“补充创新”。只读审查和修复都能由当前agent完成；使用独立检查者可提高信心，但不以工具不存在阻塞任务。

## 工具能做与不能做

`audit_project.py --stage submission`检查已登记的题目、运行指纹、数值主张与必要审查记录。它不能读懂全部论文或证明公式正确、确认人真的独立完成、识别所有身份痕迹、核实引用内容或保证获奖。工具过关之后仍需针对题面的实际审阅；不能倒过来只为过工具填字段。

手动复核至少覆盖：

- 看最核心的公式、一个可手算例和最终输出；用第二种方式复算关键指标。
- 抽取摘要中的每个关键数字，追踪至对应运行、图表/推导及比较基线。
- 核对保密/匿名范围，包括封面例外、图中截图、附录代码、绝对路径、文件属性和修订痕迹；不要删掉主办方要求的实名封面。
- 打开最终PDF，按本届模板核对摘要、页码、图表、公式、参考文献及完整性。
- 确认生成的AI声明与真实日志一致，受限的核心任务并非由AI代做后再补签名。

## 冻结和提交

先完成所有允许的编辑和渲染，再冻结**确切字节**。例如：

```text
python <skill-dir>/scripts/freeze_submission.py <project-dir> --file paper/final.pdf --file results/required-answer.csv
python <skill-dir>/scripts/freeze_submission.py <project-dir> --verify checks/submission_manifest.json
```

该工具记录MD5/SHA-256和大小；不会设置文件只读，也不会登录、上传、提交或生成官方回执。上传前复验；当届要求官方校验工具时还须使用该工具。提交MD5后任何重新导出、压缩、改元数据都会改变文件，不能称“只是排版没变”。

提交动作只在用户明确授权和规则允许时进行。提前准备可审阅的最终文件及清单；核对题号/队号、文件名、附件格式、文件大小与各自截止时间。需用户操作时提供简短步骤，不能把本地文件生成误报成已提交。

## 答辩/复盘

以真实贡献组织“问题难点—模型选择—关键结果—证据—局限”，准备解释最强基线、可行性、适用域和代价。对方指出反例时据证据修正，不将结果全部推给AI。没有取得答辩通知时不编造时长或晋级条件。

赛后复盘比较原方案和可验证改进，记录哪些失败来自审题、数据、模型、实现、验证或写作。完整保留当时的运行与提交版本，避免后来的修正被误当成赛中成果。
