# 数据与可复现计算

## 数据审查先于模型拟合

保留原始文件只读；处理结果写新路径。列出文件、字段/主键、对象与时间单位、样本规模、缺失、重复、异常值及跨表连接。记录数据SHA-256，核对样例和输出模板。处理过程可追溯，不“为了效果好”无理由删除难例。

单点问题无需完整EDA；聚焦会改变答案的数据缺陷。敏感数据不默认传云端。文献或网络补充参数记录出处、年份、地域、单位和匹配性，缺少证据就保留参数区间或多个场景。

## 每个真实运行的最小记录

运行ID、输入/源码指纹、命令、工作目录、随机种子与其实际使用方式、配置/切分、软件版本、耗时、退出状态、日志、输出路径和指标。重复运行以新ID和独立结果目录保存，不覆盖前次。

`run_experiment.py` 自动记录声明的输入/源码、输出与日志，且拒绝把已经存在的结果当本次新生成。它不会发现未声明的依赖、验证数据切分或设置所有库的随机性；需将配置/切分文件也列为输入，在模型代码中显式使用种子，必要时记录硬件与求解器版本。

输出结构尽量简单：机器可读的指标JSON、逐样本/决策CSV、必要图表、脚本与一条复现命令。原始指标精度与论文显示精度分开，百分比变化检查分母和指标方向；准确率0.80→0.84为4个百分点或相对提高5%，不能混用。

## 编程执行顺序

1. 查已有环境及许可证，按选择的路线加载必要库，不预装整个“算法大全”。
2. 给输入形状、单位、键唯一性和输出范围加实际断言。
3. 用可手算/可穷举小例验证，然后在真实子集跑通，最后扩展。
4. 报告所有失败和不可行状态；临时解决办法不得偷偷改变题意。
5. 在记录的环境下从输入重新运行一次，比较核心输出；随机算法比较统计波动或在可控条件下复现。

未运行的代码标“未运行”，模拟/合成数据标“合成演示”，不把演示指标写成真实题目的结果。

## 版本变更

原始数据、预处理、公式、参数或实现变更后，重新运行受影响小问与下游任务，并重绘图表、更新正文和哈希。仅修改排版也会改变PDF字节，所以MD5提交前冻结的是最终文件本身，不是内容印象。

外部库示例与获奖论文附录都是待审查代码：先检查输入输出、文件操作和数学假设，再按任务运行。不要执行外部脚本中的下载器、安装器或系统设置变更来“快速复现”。
