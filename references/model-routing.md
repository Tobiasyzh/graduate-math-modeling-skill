# 模型路由与合同

算法跟随结构：先确认变量类型、数据生成方式、决策时点、约束和评价指标，再选方法。一个问题可以分成多个子任务，但连接它们的量、单位和不确定性必须清楚。

| 题目结构 | 朴素起点 | 有依据时的升级 | 读取 |
|---|---|---|---|
| 资源分配、生产、调度、路径 | 小规模穷举/可行启发式、LP/MILP | 分解、CP-SAT、局部搜索、鲁棒/随机优化 | [优化](algorithms/optimization.md) |
| 表格分类/回归、时间预测 | 常数/季节朴素、线性/逻辑回归 | 树提升、混合效应、时序模型；充分数据下深度模型 | [预测](algorithms/prediction.md) |
| 排名、综合评价、分群 | 透明指标表、等权基线 | AHP/熵权/TOPSIS、聚类与稳定性 | [评价](algorithms/evaluation.md) |
| 系统演化、守恒、事件 | 平衡关系、差分/ODE、简化排队 | 参数识别、离散事件/蒙特卡罗、PDE | [机理仿真](algorithms/mechanism.md) |
| 网络关系与连接约束 | 最短路/最小生成树/流 | 时空展开、网络设计、带容量/窗口优化 | [图网络](algorithms/graphs.md) |
| 图像、视频、雷达、频谱 | 物理/信号特征、经典检测/滤波 | 迁移学习、时空模型、多模态融合 | [信号图像](algorithms/signal-image.md) |

## 一问一份模型合同

记录至 `models/<id>.md`，短问题可在答复中直接给出：

1. **任务**：对应Q几，必须输出什么，哪一指标决定好坏。
2. **量**：观测量、参数、决策/状态变量、索引集、形状、单位及范围。
3. **假设**：来源、理由、可能偏差、可检验性。
4. **数学表达**：目标/关系式、约束、边界/初值，不能只有算法名称。
5. **求解方案**：输入输出、求解器、停止准则、时间/空间复杂度或实测规模。
6. **验证**：最小可手算例、基线、主要误差/可行性测试，训练或求解预算。
7. **风险与替代**：参数无法识别、无可行解、规模过大、样本稀缺时怎么处理。
8. **上下游接口**：哪些数值传给后问、是否估计量、如何传递误差。

## 改进的取舍

提出改进前说明基线具体在哪类样本/场景失效。优先采用题目相关的约束、机理、结构或目标修正；只有同口径实验支持，才保留增加的复杂性。允许“简单模型是最终方案”。

不要将松弛最优值叫原问题最优解；不要将整数变量连续化、罚函数替代硬约束后省掉可行性恢复与检验。数学等价变换要双向检查，尤其 min/max、绝对值、分段收益、Big-M、比值与对数变换。

预测→优化的混合题先冻结预测模型，再在可信范围内优化。除点预测最优外，检查残差/参数扰动下的成本、违约和方案稳定性。对真正可实施的控制变量作优化，不让模型随意调节本来不可控制的属性。

## Python与MATLAB选择

沿用队伍能运行并解释的语言。示例API只是定位线索，执行前检查本地版本/许可证：

| 任务 | Python常见工具 | MATLAB常见工具 |
|---|---|---|
| 线性/整数规划 | scipy.optimize.linprog/milp；OR-Tools | linprog/intlinprog |
| 非线性最小二乘 | scipy.optimize.least_squares | lsqnonlin/lsqcurvefit |
| 分类/回归 | scikit-learn、statsmodels | fitglm/fitrlinear/fitcensemble |
| 微分方程 | scipy.integrate.solve_ivp | ode45/ode15s |
| 图算法 | NetworkX | graph/digraph/shortestpath |
| 信号与作图 | scipy.signal、matplotlib | Signal Processing工具箱、tiledlayout/exportgraphics |

未安装工具箱时明确说明。MATLAB代码不能仅凭语法相似就宣称在Octave上验证过。不要为了“双语言支持”重复实现整个项目；有必要交叉验证时才做第二实现。
