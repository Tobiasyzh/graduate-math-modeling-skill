# 十分钟走通证据链

这是一道原创合成练习，不是获奖论文数据，也不用于证明技能的获奖效果。三个项目的成本/收益分别为A=(4,7)、B=(3,5)、C=(3,5)，预算6，每个项目最多选一次，目标最大化总收益。它故意让“单位收益最高优先”的直觉失败，便于手算审查。

```text
python <skill-dir>/scripts/make_demo.py <new-empty-project-dir> --plot
```

Python 3.10+；`--plot`另需matplotlib，未安装时去掉该选项即可完成计算。不要对已有赛题目录运行示例；工具拒绝覆盖非空目录。各次复跑用新目录，不复用旧运行编号或旧输出。

程序真正执行：初始化→复制合成数据与源码→贪心与完整枚举→独立重算可行性→七种预算扫描→记录哈希与指标→生成结果段与图（可选）→草稿证据审计。人工检查选择B、C的收益是否为10，贪心选A的收益是否为7；检查全部八种组合是否已覆盖。最优性证据只适用于这个小型二元问题。

打开`project.json`看每问如何关联运行，打开`claims.json`看正文主张如何关联指标，打开`runs/demo-01/run.json`看真实命令和输入/输出哈希。图若生成，查看`figures/budget-benefit.png`，注意它是确定性预算扫描，不是随机重复实验；不能添加虚构误差棒。

然后有意修改`src/solve_allocation.py`的一个注释，再运行：

```text
python <skill-dir>/scripts/audit_project.py <demo-project-dir> --stage draft
```

`--stage submission`应失败，因为AI日志、人工审查等没有完成。这是预期行为，示例不会替人捏造审核通过，也不会替用户向比赛平台提交。
