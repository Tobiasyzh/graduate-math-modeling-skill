# 研究生数学建模全流程 Skill

这是一个面向研究生数学建模比赛的 Codex Skill，目前版本为 1.0.1。

项目涵盖选题、审题、建模、编程求解、结果检查、图表制作、论文修改和交稿前检查。使用时既可以从选题开始完整推进，也可以只检查一个公式、一段代码、一张图或一段论文。

适用范围包括华为杯中国研究生数学建模竞赛、MathorCup 研究生组，以及研究生校赛和省赛。项目更重视实际过程能不能核对：模型需要真正运行，论文中的数字需要对应到结果文件，题目、数据或代码发生变化后，旧结果也需要重新检查。

## 它可以帮你做什么

- 比较几道题与队伍能力是否匹配，并安排一个短时间内能跑通的小实验，避免在不合适的题目上耗太久。
- 把每个小问拆清楚，包括已知数据、要解决的问题、变量、约束、算法、检查方法和备用方案。
- 根据任务选择预测、优化、评价、机理仿真、图网络或信号图像方法，不为了显得复杂而堆算法名。
- 帮忙写和修改 Python 或 MATLAB 代码，记录每次运行使用的数据、代码、参数和结果。
- 检查数据泄漏、约束是否满足、求解器状态、敏感性、外推风险，以及图表和论文中的数字是否一致。
- 根据已经跑出来的结果写摘要和正文，也可以在提交前检查匿名、引用、AI 使用说明和最终 PDF。

如果时间很紧，它会先想办法把所有小问做出一个能运行的基础版本，再决定哪一部分最值得继续改。它不会承诺奖项，也不会把图画得多、论文写得长或者算法名字多当成水平高。

## 安装

下载或克隆这个仓库：

```text
git clone https://github.com/Tobiasyzh/graduate-math-modeling-skill.git
```

把仓库内容放到 Codex 的技能目录，并保证 `SKILL.md` 位于技能根目录。建议使用下面这个目录名：

```text
~/.codex/skills/grad-math-modeling/
```

`dist/grad-math-modeling.skill` 是已经打包并校验过的版本，适合下载、备份或分享。

## 怎么用

如果要从头开始做一道题，可以这样说：

```text
$grad-math-modeling 这是赛题、附件和剩余时间。请先审题并比较选题，给出两小时内能验证的小模型，然后直接开始做。
```

如果只想解决一个问题，也可以直接说清楚范围：

```text
$grad-math-modeling 检查这个 MILP 线性化是否正确，给一个反例，再用小程序验证。不要重建整个项目。
```

```text
$grad-math-modeling 检查这份预测代码有没有数据泄漏，修好以后重新运行，并说明指标为什么发生变化。
```

```text
$grad-math-modeling 只根据现有结果文件修改摘要，不要补写没有做过的实验和数字。
```

第一次使用时，最好把这些信息一起给它：比赛名称和年份、现在是备赛还是正式比赛、题目和附件、真正的截止时间、队员会什么、电脑配置，以及已经写好的代码或结果。缺少这些信息也能开始，但有些建议只能先当作临时方案。

## 先跑一个简单例子

仓库里放了一个原创的资源分配小例子。它只有三个项目，可以把全部组合都算一遍，所以很容易检查代码有没有给出真正的最优解。

```text
python scripts/make_demo.py examples/my-first-run --plot
```

这个命令会生成结果、敏感性数据和图，并把论文里的数值结论与实际运行结果对应起来。例子中，完整枚举得到的收益是 10，按单位收益比贪心得到的收益是 7。这个例子只是用来演示工作过程，不代表某种算法在比赛中一定更好。

已有项目可以直接使用，不需要重新建目录。如果想新建一个练习项目，可以运行：

```text
python scripts/init_project.py <project-dir> --name "队伍练习" --mode practice --language python
```

## 仓库里有什么

| 路径 | 内容 |
|---|---|

## 测试情况

仓库里的工具目前有 14 项集成测试。在 Python 3.12.7 下运行时，14 项测试全部通过。测试内容包括程序运行失败、输出文件缺失、NaN 和 Infinity、路径跑出项目目录、输入或代码变化后旧结果失效，以及交稿文件被改动后的检查。

运行测试：

```text
python tests/test_tools.py
```

另外设置了三组模拟任务，用来检查选题、公式核验和论文数字修改。前两组完成了启用和不启用 Skill 的对照，两边都通过了 13 条检查。这至少说明 Skill 没有破坏原来的解题能力，但任务数量还太少，不能据此说它一定能提高成绩。第三组遇到了传输中断，所以没有计分。详细记录在 [开发与验证说明](docs/DEVELOPMENT_AND_VALIDATION.md)。

## 比赛时需要注意

比赛规则每年都可能改，特别是 AI 使用范围、匿名要求、论文模板、附件格式和提交时间。这个仓库保存的是开发时查到的资料，正式比赛时还是要重新打开主办方当年的通知。

不要把没有公开的赛题、个人数据、医疗数据或其他队伍的作品上传到没有得到授权的网站。用过哪些 AI 工具、做了什么，也应该按照比赛要求如实记录。求解器显示成功，只能说明它成功求解了你输入的模型，不能反过来证明模型和公式一定写对了。

## 资料来源

开发过程中参考了三套公开的数学建模 Skill，也查阅了华为杯和 MathorCup 的官方材料。获奖论文部分精读了七篇能够核对队号、奖项和论文全文的作品，同时保留了一篇资料相对不完整的补充样本。

仓库没有收录这些论文的原始 PDF、获奖名单或第三方代码，只保留整理后的方法、来源位置和项目脚本。具体来源可以看 [references/sources.md](references/sources.md) 和 [references/source-catalog.json](references/source-catalog.json)。获奖论文适合用来学习问题拆分、结果验证和论文表达，但不能直接复制，也不能证明照着某种方法做就一定能获奖。
